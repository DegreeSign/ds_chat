Models

You don't pick. It does.

With no override, the package picks the GPU build when WebGPU exists and the CPU build when it does not. Both are 2B models: small enough for a device, good enough for captions, tags and short answers.

Qwen3-VL 2B

Straight talk.

These are 2B models. They are excellent at captions, tags, summaries, short answers and private drafts. They are not the model you ask to write a novel. The first reply on a phone can take a minute. After that, it is local.

Install

One command to local.

No key, no account, no server. Add the package, call createChat, render in any UI. Works in React, a worker, a Node script or plain JS.

npm install @degreesign/chat

No config, no key. The first call downloads the weights once; later calls reuse the cache.

Vite Workers Node 24 React Next.js 
import {
    LlmRole,
    createChat,
} from "@degreesign/chat";

        {

        },
        {
            role: LlmRole.user,

FAQ

The questions you're about to ask.

No jargon, no asterisks. Here is what it does and what it does not.

Do I need a GPU?

No. WebGPU is used when the browser has it. Without an adapter, the CPU engine runs the same call. Phones and older laptops work.

How big is the download?

About 1.5 GB on CPU or 2.0 GB on GPU. It downloads once, resumes after a reload, and stays cached until you clear it.

Does it really work offline?

Yes. After the first download, the weights and the engine run locally. The package makes no network request to answer.

What happens if I clear the cache?

The next send downloads it again. No hidden copy, no account.

How is it free?

The package is MIT and there is no per-reply fee. You pay for the device and the one-time download, not for each answer.

Does it collect anything?

No key, no server and no upload. The package writes no history; your app owns the data.
